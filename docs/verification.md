# 검증 기록

## 0.1.1 — 명령 한 번으로 설치

- Python 테스트 42개: 기존 편집/복구 검사에 설치 순서, 동의 취소, 종료 실패,
  재실행 실패, 이미 적용된 앱, 빌드 캐시, 실행 권한 복구, Python 선택 회귀 검사를 추가했습니다.
- 자체 AppKit 광고 영역 검사 18개는 그대로 유지됩니다.
- 자체 제작한 임시 앱으로 정상 종료, 동일한 실행 파일 이름을 가진 다른 앱 보존,
  이미 종료된 앱 처리, 재실행, 종료 거부 시 강제 종료하지 않음을 검사했습니다.
- 실제 설치된 카카오톡에는 이 설치 명령을 실행하지 않았습니다.
- 관리자 권한 분기는 코드 리뷰 범위이며, 이 검증에서 실제 관리자 권한 패치는 실행하지 않았습니다.

## 0.1.0 — 패처 코어

검증일: 2026-10-27. 대상: KakaoTalk macOS 26.9.0 (2006), Apple Silicon.

- Python 테스트 24개: Mach-O 편집, 위험 동의, 버전/해시 제한, 실행 중 앱 거부,
  실제 파일을 이용한 적용·복구, 서명/교체 실패, 중단 복구, 심볼릭 링크, 업데이트 보호.
- 네이티브 AppKit 검사 18개: 광고·구분선 높이 0, 콘텐츠 확장, 높이/숨김값 복원 시도,
  리사이즈, 교체/해제된 뷰, 무관한 객체 보존, 늦은 클래스 등록과 중복 훅 방지.
- 실제 공식 앱의 임시 복사본에서 Universal 두 아키텍처 로드 명령 추가,
  원본 entitlements 유지, 서명 검증, 백업 복구 후 원본 실행 파일 해시 일치를 확인했습니다.
- 별도 식별자·임시 홈을 쓰는 복사본에서 배포용 페이로드를 실제 로드했습니다.
  원본 `FSMainViewController`와 원본 nib의 outlet 연결 시 광고·구분선 높이가
  자동으로 0이 되고 콘텐츠가 확장됐습니다. 검사 도구의 수동 collapse 함수는 호출하지 않았습니다.
  이 격리 실험에서만 로그인 모델을 요구하는 화면 초기화 콜백을 생략했습니다.
  **배포 페이로드는 해당 콜백을 변경하지 않습니다.**
- 별도 코드 리뷰에서 발견된 비정상 Mach-O의 offset-zero 섹션 처리 오류는
  회귀 테스트가 실패하는 것을 확인한 뒤 수정했습니다.
- 배포 ZIP과 Git 제외 규칙을 검사했습니다. 카카오 원본 앱·리소스 및 로컬 분석 자료는 제외됩니다.

확인 범위에 포함되지 않는 항목:

- 로그인한 실제 계정의 로그인·송수신·장기 사용과 계정 안전성.
- Intel 하드웨어에서의 실행. x86_64 빌드는 생성했습니다.
- 전원 차단·디스크 고장 시의 완전한 복구 보장, 동일 사용자 권한의 악의적인 파일 변경.

이 결과는 실험용 패처의 제한된 검증 결과이며 카카오의 승인이나 무제재 보장이 아닙니다.
